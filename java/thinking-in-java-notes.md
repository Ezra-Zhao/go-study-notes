# Java 编程思想学习笔记

> 资料定位：本笔记依据一本 Java 思想类经典著作的章节结构整理而成。该书的特点是：不从语法手册的角度讲 Java，而是从"面向对象到底怎么思考"切入，再层层展开语言机制。适合有一定语法基础、想建立设计思维的读者。正文全部用自己的语言重写，代码示例均为手写。

---

## 一、对象入门：换一种思考方式

学 Java 最大的坎不是语法，是思维方式的切换。过程式思维问的是"先做什么、再做什么"；面向对象思维问的是"这个系统里有哪些东西，它们各自负责什么、互相怎么协作"。

一个对象 = 状态（属性）+ 行为（方法）。设计时先找名词（候选对象），再找动词（候选方法）。比如设计一个图书馆系统，名词有书、读者、借阅记录；动词有借书、还书、查询。对象之间通过发送消息（调用方法）协作，而不是直接翻对方的口袋——这就是封装的由来。

五个基本特征值得反复体会：万物皆对象、程序是对象的集合（互相发消息）、每个对象都有自己的存储（但可共享）、每个对象都有类型（class 是类型的实现）、某一特定类型的所有对象都能接收同样的消息（接口统一）。

## 二、一切都是对象

Java 里"一切都是对象"这句话有个例外：8 种基本类型不是对象（为了性能）。引用（reference）是操作对象的手柄：声明 `String s;` 只是造了个手柄，还没指向任何对象，必须 `new` 出来才真正有对象。

```java
String s;            // 只有引用，没有对象，此时用它会编译报错
s = new String("a"); // new 在堆上创建对象，s 指向它
```

对象存在堆里，引用存在栈或堆里。Java 没有指针运算，引用只能指向对象，不能做地址加减，这消灭了一大类内存错误。对象的生命周期由垃圾回收器管理，不用手动释放，但这不等于不用管内存——静态集合里长期持有用不到的对象引用，同样会泄漏。

## 三、控制程序流程

流程控制是每种语言都有的部分，Java 的 if、switch、while、for、break、continue 与 C 系语言基本一致。这里提两个容易被忽视的点：

- **标签 + break/continue**：Java 的标签机制相当于受控的 goto，可以跳出多层嵌套循环。能用，但嵌套太深本身就是代码坏味道，先考虑抽方法。
- **真假值**：Java 的条件表达式必须是 boolean，不能像 C 那样拿整数当条件。`if (x = 1)` 这种写法在 Java 里直接编译不过，这其实是语言在保护你。

## 四、初始化和清除

"初始化"是 Java 设计得最用心的地方之一。字段有默认值（数字 0、boolean false、引用 null），局部变量没有——用之前必须显式赋值，编译器会检查。

构造器保证对象一出生就是可用状态。构造器可以重载，`this(...)` 可以在一个构造器里调用另一个，避免重复代码。初始化顺序：静态成员（类加载时一次）→ 实例字段/实例块 → 构造器。继承时先父后子。

"清除"对应的是垃圾回收。Java 没有析构函数，`finalize()` 已经被废弃，不要用。需要释放的资源（文件、连接）应该用 try-with-resources 或显式 close，而不是指望 GC。GC 只管内存，不管文件句柄。

## 五、隐藏实现过程

封装的核心是访问控制：`private` → 包访问 → `protected` → `public`，权限由小到大。原则是"最小暴露"：能 private 就不放 public。

为什么要隐藏？因为实现会变，接口要稳。把字段藏起来、只暴露方法，未来你想把内部存储从数组换成链表，调用方一行代码都不用改。这就是"针对接口编程"的底气。包（package）是更大一层的封装单位，相关类放一起，对外只暴露必要的类。

## 六、类再生：复用的三种方式

代码复用有三条路：

1. **组合**：在新类里放一个旧类的对象，用它的功能。"has-a"关系，最灵活，优先用它。
2. **继承**："is-a"关系，子类自动获得父类行为，还能重写。威力大但耦合紧——父类一改，所有子类都受影响。
3. **代理**：持有对象并转发调用，介于两者之间，常用于不想暴露继承关系、又想完整复用接口的场景。

继承有个微妙点：向上转型后，子类新增的方法就"看不见"了，只能用父类声明的接口。这恰恰是多态想要的效果——调用方只依赖稳定的父类接口。

final 在这里的作用：`final` 类不能被继承，`final` 方法不能被重写。设计类库时，把不希望被改动的部分 final 修饰，是保护设计意图的手段。

## 七、多形性：面向对象的皇冠

多态 = 同一个调用，运行时表现出不同行为。前提是继承 + 重写 + 父类引用指向子类对象。Java 的方法调用默认是动态绑定的（虚方法调用），private、static、final 方法除外（它们在编译期就确定了）。

```java
class Shape { void draw() { System.out.println("shape"); } }
class Circle extends Shape { void draw() { System.out.println("circle"); } }

Shape s = new Circle();
s.draw();   // 输出 circle：运行时看的是对象的实际类型
```

多态的价值在于可扩展性：写一段处理 `Shape` 的代码，以后新增 `Triangle`，老代码不用动。这就是"开闭原则"（对扩展开放、对修改关闭）的语言级支撑。设计模式里一大半都是在玩多态的花样。

构造器里不要调用可被重写的方法：子类对象还没初始化完，父类构造器却调到了子类的方法，会读到未初始化的字段，这是经典 bug。

## 八、对象的容纳：容器

数组长度固定、类型固定，装对象不够灵活，于是有了容器。容器的核心接口：

- `Collection`：`List`（有序可重复）、`Set`（不重复）、`Queue`（队列）。
- `Map`：键值对，键不重复。

选型看需求：要顺序用 List，要去重用 Set，要映射用 Map。Java 5 引入泛型后，容器可以声明元素类型，`List<String>` 在编译期就拦住放错类型的代码，取出来也不用强转。迭代器（Iterator）统一了遍历方式，是"把遍历逻辑从容器里抽出来"的设计。

## 九、违例差错控制：异常

异常机制把"错误处理代码"和"正常业务代码"分开。没有异常机制的年代，错误靠返回码层层上传递，业务逻辑被淹没在错误检查里。

Java 的异常分受检（checked）和非受检（unchecked）。受检异常强制调用方处理或声明，初衷是好的，但实践中经常导致到处都是 `throws` 和空 catch。现代框架更倾向用非受检异常 + 统一拦截。记住三条实践原则：

1. 异常只用于异常情况，不做流程控制。
2. 捕获后要么处理、要么包装成更有意义的异常往上抛，不要吞掉。
3. finally（或 try-with-resources）负责资源释放，和业务异常处理分开想。

## 十、Java IO 系统

Java 的 IO 是装饰器模式的教科书案例。`InputStream`/`OutputStream` 处理字节，`Reader`/`Writer` 处理字符；`BufferedInputStream` 给任意输入流加上缓冲能力，一层包一层：

```java
BufferedReader br = new BufferedReader(
        new InputStreamReader(
                new FileInputStream("data.txt"), "UTF-8"));
```

这种设计的精髓：功能（缓冲、字符转换）和数据源（文件、网络、内存）正交组合，不用为每种组合写一个类。学 IO 时画一张类图，把"节点流"和"处理流"分开，脉络就清楚了。

NIO 引入了通道（Channel）和缓冲（Buffer），面向块而非面向流，适合高吞吐场景。日常文件读写用传统 IO 足够，网络服务器才需要认真考虑 NIO。

## 十一、运行期类型鉴定（RTTI）

RTTI 是在运行时搞清楚"这个引用到底指向什么类型"的机制。`instanceof` 做类型检查，`Class` 对象携带类型的元信息，反射（Reflection）则能进一步列出和调用成员。

RTTI 的典型用途是多态兜不住的时候：比如反序列化、框架要根据注解做事。但业务代码里频繁用 `instanceof` 做类型分支，通常是设计没到位的信号——先想想能不能用多态把分支消掉。

类加载器（ClassLoader）负责把字节码搬进 JVM。双亲委派模型：先问父加载器，父找不到自己再找，保证核心类不被冒名顶替。理解它，jar 包冲突、`ClassNotFoundException` 这类问题就有排查思路了。

## 十二、传递和返回对象

Java 里对象传递的是引用的拷贝——方法拿到的引用和调用方指向同一个对象，所以方法内改对象状态，调用方看得见；但方法内让引用指向新对象，调用方不受影响。记住"引用拷贝"四个字，就不会被"Java 是值传递还是引用传递"的争论绕晕：形式上是值传递（传的是引用的值），效果上能改对象状态。

返回对象时注意别暴露内部可变状态：返回集合字段的防御性拷贝，或返回不可修改视图（`Collections.unmodifiableList`），否则外部代码能直接改你的内部数据。

## 十三、多线程

Java 把线程做成语言级特性。两种创建方式：继承 `Thread` 或实现 `Runnable`（推荐后者，解耦任务和线程）。线程安全靠同步：`synchronized` 保证同一时刻只有一个线程进临界区，`volatile` 保证变量修改对其他线程可见（但不保证原子性）。

```java
private int count = 0;
public synchronized void increment() { count++; }  // 同一时刻只允许一个线程执行
```

死锁的四个条件（互斥、持有并等待、不可剥夺、循环等待）要背熟，排查死锁先看线程 dump 找循环等待链。现代并发编程优先用 `java.util.concurrent` 包里的工具（线程池、并发集合、锁），少自己写 `wait/notify`。

线程的本质是"任务切换的成本换响应性"，共享可变状态是万恶之源。能不变就不变（immutable），能隔离就隔离（ThreadLocal、消息传递），最后才上锁。

## 十四、网络编程

`Socket` 是网络编程的基本抽象：客户端 `new Socket(host, port)` 连上去，服务端 `ServerSocket.accept()` 等连接，连上之后两边拿到的都是流，读写流就是收发数据。URL 类处理更高层的 HTTP 等协议。

网络编程的核心难点不在 API，在异常和超时：连接会断、对端会慢、数据会分片。所有网络调用都要设超时、做重试、想好降级。先写通单线程版，再考虑 NIO 或线程池处理并发。

## 十五、设计范式与项目实践

设计模式是前人总结的"常见问题的常见解法"。先掌握几个最常用的：

- **单例**：全局唯一实例，注意多线程下的实现方式。
- **工厂**：把 `new` 的决策集中到一处，调用方只认接口。
- **观察者**：一对多的通知机制，事件驱动的基础。
- **装饰器**：动态加功能，IO 流就是例子。
- **策略**：把算法封装成可互换的对象，消灭 if-else。

学模式别背 UML 图，看它解决了什么"变"：把变化的部分抽出来、把不变的部分定下来，这就是所有模式的共同思想。最后一定要做完整项目——知识只有在解决真实约束（需求变更、性能、bug）时才会长到身上。

## 常见坑

1. 构造器里调用可重写的方法，子类字段还没初始化就被读取。
2. `==` 和 `equals` 混用：比较对象内容一律用 `equals`。
3. 异常被吞掉：空 catch 块是埋雷，至少记日志。
4. 在循环里做字符串 `+` 拼接，性能被临时对象拖垮。
5. 以为 GC 会关文件：资源必须手动释放，try-with-resources 是正解。
6. 多线程下共享可变状态不上锁，或者滥用 `volatile` 当锁用。
7. 过度设计：为了"以后可能用"提前上模式，代码越写越重。
