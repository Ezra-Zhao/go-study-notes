# Python 编程：从入门到实践 · 学习笔记

**本书定位**：一本"先学基础、再做项目"的 Python 书，前半本把语法地基打牢，后半本用三个完整项目（游戏、数据可视化、网站）把知识点串成能拿出手的作品，适合想"学完就能做东西"的人。（本笔记依据某 Python 实战入门书的章节结构整理。）

## 第一部分 基础知识

### 1. 起步：环境与第一行代码

- 环境搭建是学编程的第一道真实门槛：装解释器、配编辑器、跑通第一句打印。很多人在这里卡住不是因为难，而是因为"不知道哪一步算成功"——标准是：能新建一个 .py 文件并运行看到输出，环境就算通了。遇到报错先看最后一行，它通常直接告诉你错在哪。
- 第一句代码的价值在于"建立反馈回路"：改一行、运行、看结果。这种"动手—看到变化"的循环，是后面所有学习的心态基础。不要在起步阶段纠结版本细节，先让程序跑起来。

### 2. 变量和简单数据类型

- 变量是"数据的名字"，Python 的变量不需要提前声明类型，赋值时自动确定。数字、字符串是最常用的两种类型：数字做计算，字符串做展示和拼接。类型错配（比如数字和字符串直接相加）是新手最常见的报错，记住"不同类型先转换再运算"。
- 字符串操作是日常高频技能：大小写转换、去空格、拼接、格式化输出。f-string（f"..."）是目前最直观的格式化方式，把变量直接嵌进字符串里，代码读起来像自然语言。能熟练拼字符串，打印日志、生成报表就都顺手了。

### 3. 列表简介与操作列表

- 列表是"有序的一串东西"，用方括号装起来，第一个元素的下标是 0 不是 1。这个"从 0 开始数"是所有编程语言的通用约定，早点习惯。增删改查四个动作练熟，列表就成了你手里最顺手的容器。
- 遍历（for 循环）是列表的灵魂：对列表里每个元素做同一件事。配合切片（取其中一段）、推导式（一行生成新列表），能写出非常紧凑的数据处理代码。排序和统计（max/min/sum/len）是内置的，不用自己写循环去算。
- 操作列表时要注意"改的是原列表还是得到了新列表"：sort() 是原地改，sorted() 返回新的。这个区别在调试时很关键——数据"莫名其妙变了"，多半是某个地方原地修改了共享的列表。

### 4. if 语句：让程序做判断

- if 的本质是"分支"：条件成立走一条路，不成立走另一条。elif 处理"多选一"，多个条件按顺序判断，命中一个就停。写条件时先想清楚"所有可能的情况有没有被覆盖"，漏掉的分支就是未来的 bug。
- 比较运算和布尔逻辑（and/or/not）是条件的心脏。检查"元素在不在列表里"用 in，这是 Python 里非常地道的写法。条件写复杂了就拆成变量：先把"是否成年""是否有票"算成 True/False，再组合判断，可读性立刻提升。

### 5. 字典：用名字存数据

- 字典是"键—值对"的集合：列表靠位置找东西，字典靠名字找东西。比如存一个人的信息，用 {"name": "Ezra", "age": 30} 比用列表按位置记直观得多。键必须是唯一的，取值时用 get() 可以避免键不存在时崩溃。
- 字典的遍历有三种姿势：遍历键、遍历值、同时遍历键值对，根据需求选。嵌套是字典的进阶用法——列表里装字典、字典里再装字典，能表达现实世界里"一对多"的结构。数据一复杂，先画出它的嵌套结构再写代码。

### 6. 用户输入和 while 循环

- input() 让程序第一次能"听人说话"，但它拿到的永远是字符串，要做计算必须先转成数字类型。这是"类型转换"最真实的应用场景，也是报错高发区：用户输入了字母，int() 就会炸，所以转换前后要做合法性检查。
- while 循环适合"不知道要重复多少次"的场景，比如"用户输入 quit 就退出"。它和 for 的分工要分清：次数确定用 for，条件驱动用 while。写 while 必须保证循环体内有让条件变化的语句，否则就是死循环；需要时用 break 主动跳出、continue 跳过本轮。

### 7. 函数：把重复的逻辑装起来

- 函数解决的是"同样的步骤要做好几遍"的问题：写一次，到处调用。参数是调用时传进来的原料，可以设默认值，也可以按名字传参。返回值是函数交出来的成品，一个函数最好只干一件事，名字要能说出它是干什么的。
- 参数传递的细节值得吃透：位置参数按顺序对号入座，关键字参数按名字对号入座；*args 收多余的位置参数，**kwargs 收多余的关键字参数。模块则是"把函数按主题装进不同的文件"，import 就是去别的工具箱里拿工具。

### 8. 类：面向对象的大门

- 类是"图纸"，对象是"按图纸造出来的东西"。把相关的数据（属性）和操作（方法）打包成一个类，代码就从"散落的函数"变成了"有职责的零件"。__init__ 是对象的"出生设置"，每个对象的数据互相独立，这是面向对象最重要的一课。
- 继承让新类"站在旧类的肩膀上"：子类自动拥有父类的一切，只写新增和改写的部分。super() 用来调用父类的方法，避免重复写初始化逻辑。记住一条实践准则：只有"是一种"的关系才用继承，否则用组合（一个类里包含另一个类的对象）更稳。

### 9. 文件和异常：程序要和外部世界打交道

- 文件读写是程序"持久记忆"的方式：open 打开、读写、close 关闭，用 with 语句能自动关闭，推荐无脑用。读大文件用逐行读，别一次全塞进内存；写文件注意模式是覆盖（w）还是追加（a），选错会把旧数据冲掉。
- 异常处理是"给可能出错的代码买保险"：try 里面放冒险的代码，except 规定出错了怎么办。文件不存在、用户输入非法、网络中断都属于"运行时才知道"的错误。原则是：只捕获你知道如何处理的异常，捕获后要么恢复、要么给用户清晰的提示，不要静默吞掉。

### 10. 测试代码：给程序上保险

- 测试的核心思想很朴素："写一段代码，自动检查我的代码对不对"。不用每次都靠眼睛看输出，跑一遍测试就知道功能有没有被改坏。先写"期望的结果是什么"，再写检查逻辑，这就是断言（assert）的用法。
- 测试的价值在"改代码"时最大：重构、加功能时跑一遍测试，绿了就说明没改坏旧功能。入门阶段不用追求覆盖率数字，养成"写完功能顺手写几个关键用例"的习惯，长期收益巨大。测试本身也要保持简单，一个测试只验证一件事。

## 第二部分 项目实战

### 项目一：做一个 2D 射击小游戏

- 游戏项目的真正收获不是"会做游戏"，而是学会"游戏主循环"这个模型：不断地"处理输入—更新状态—画出来"，所有实时程序（游戏、动画、监控面板）都是这个套路。理解了主循环，就理解了一大类程序的骨架。
- 这个项目把前半本书的知识点全用上了：用类表示飞船、子弹、敌人（面向对象），用列表管理屏幕上所有的子弹和敌人（容器+遍历），用事件处理响应键盘（输入），用碰撞检测判断命中（条件判断）。它证明了一件事：基础语法组合起来，就能做出看得见摸得着的东西。
- 做项目的通用方法是"先让最小可玩版本跑起来，再一点点加功能"：先让飞船能动，再加子弹，再加敌人，最后加计分。一次只解决一个问题，卡住了也知道是卡在哪一层。这种增量开发的习惯，比游戏本身更值钱。

### 项目二：数据可视化

- 数据可视化的起点是"先把数据变成图，再用眼睛找规律"。折线图看趋势、散点图看分布、柱状图做对比，选对图类型，数据自己会说话。画图之前先想清楚"你想回答什么问题"，图是手段，结论才是目的。
- 真实数据很少是干净的：CSV 表格、JSON 接口返回的数据，都要先清洗（缺值、格式不对、类型不对）再画图。写代码读文件、解析结构、提取字段，这一整套"拿数据—洗数据—画出来"的流程，是数据工作的标准动作，换什么工具都一样。
- 从公开 Web API 拿数据是这个项目最实用的部分：发请求、拿到 JSON、解析、展示。现代程序大量通过 API 交换数据，学会"读一份 API 返回、取出自己要的字段"，就打开了和外部世界对接的大门。记得做异常处理，网络请求随时可能失败。

### 项目三：用 Django 建一个网站

- Web 开发的核心模型是"请求—响应"：浏览器发来一个网址请求，服务器找到对应的处理函数，返回一张页面。Django 把这套流程封装成了"路由配视图"的固定套路：网址对应哪个函数、函数返回什么内容，照着框架的规矩填进去就行。
- 数据库是网站的记忆：用户信息、文章内容都存在表里。用 Django 的模型（Model）定义"一张表长什么样"，框架自动帮你建表、增删改查，不用手写 SQL。理解"模型对应表、对象对应行"这个映射，数据库就不再神秘。
- 做网站项目最大的体会应该是"分层"：网址路由管"找谁"，视图函数管"做什么"，模板管"长什么样"，模型管"数据怎么存"。每一层只操心自己的事，改页面样式不用碰数据逻辑。这种分层思想在所有大型项目里都通用。

## 手写代码示例（已在本机 Python 3.12 验证通过）

下面这段代码把"类 + 异常 + 测试"三个章节的要点串在了一起：一个带校验的银行账户类，外加一组手写的测试函数。

```python
def add(a, b):
    return a + b


class BankAccount:
    """一个简单的银行账户类：余额只能通过方法修改"""
    def __init__(self, balance=0):
        self.balance = balance

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("存款金额必须为正数")
        self.balance += amount

    def withdraw(self, amount):
        if amount > self.balance:
            raise ValueError("余额不足")
        self.balance -= amount


def test_add():
    assert add(2, 3) == 5, "2+3 应该等于 5"
    assert add(-1, 1) == 0, "-1+1 应该等于 0"
    print("add() 测试通过")


def test_account():
    acc = BankAccount(100)
    acc.deposit(50)
    assert acc.balance == 150
    acc.withdraw(30)
    assert acc.balance == 120
    try:
        acc.withdraw(1000)
    except ValueError:
        print("透支被正确拒绝")
    else:
        raise AssertionError("透支应该抛异常")
    print("BankAccount 测试通过")


if __name__ == "__main__":
    test_add()
    test_account()
```

## 常见坑

1. input() 返回的是字符串：要做数学运算先转 int/float，转之前先校验用户输入是否合法。
2. 列表下标从 0 开始：取最后一个元素用 `lst[-1]`，循环取数注意别越界。
3. 在遍历列表的同时删除元素：会导致跳过某些元素，先收集要删的、遍历完再删，或遍历副本。
4. 字典直接用 `d[key]` 取不存在的键会崩：不确定键是否存在时用 `d.get(key)`。
5. 文件写入模式 w 会清空旧内容：想追加用 a，写之前确认你要的是哪种。
6. 异常捕获太宽泛：`except Exception` 一把梭会把真正的 bug 藏起来，只捕获你预料到的类型。

## 练习建议

1. 每章的"动手试一试"不要跳过：看懂和会写是两回事，手指敲过一遍才算数。
2. 给上面的 BankAccount 加"转账"方法（从一个账户转到另一个账户），并补一条"余额不足时转账失败"的测试。
3. 自己定一个小项目：比如"家庭记账本"（文件存数据、字典表结构、函数做统计），把第一部分的知识点串起来用一遍。
4. 刻意练习"先写测试再写功能"：挑一个小函数，先写 assert 期望，再实现，看测试由红变绿。
