# PyCharm 高效使用指南（IDE 通用用法笔记）

> 资料定位：本笔记依据某 IDE 中文指南的章节结构整理，只讲 IDE 本身的通用能力——安装选择、运行调试、编辑效率、搜索导航、版本控制、环境与解释器、远程开发、插件工具。不涉及任何课程或机构品牌。

## 一、安装与版本选择：先选对，再折腾

PyCharm 分社区版（免费）和专业版（付费）。纯写 Python 脚本、跑数据分析，社区版完全够用；要做 Web 开发、连数据库、用远程解释器，再考虑专业版。建议：

- 装最新稳定版，别追着尝鲜版跑，稳定压倒一切；
- 安装时勾选"关联 .py 文件"，双击脚本直接用 IDE 打开；
- 建第一个项目时就选"新建虚拟环境"当解释器（见第六节），别用系统全局 Python 裸奔，依赖冲突会教你做人。

## 二、运行与调试：断点是程序员的显微镜

**运行 vs 调试。** 点"运行"是让程序一口气跑完；点"调试"是让程序在你指定的地方停下来，任你检查。排查 bug 靠的不是 print 大法，而是断点。

**四种断点要会用。**

- **行断点**：点行号右侧，程序跑到这行就停。最常用。
- **条件断点**：右键断点加条件，比如循环 1000 次只想看第 500 次，条件写 `i == 500`。没有它，你按 500 次 F8 吧。
- **异常断点**：程序抛异常时自动停在抛出的位置，抓"闪退但不知道哪行"的问题神器。
- **临时断点**：只停一次就自动消失，适合快速验证猜想。

**三个单步要分清。** 停在断点后：Step Over（单步执行，不进入函数内部）、Step Into（进入函数内部看细节）、Step Out（从当前函数跳出来）。新手最常见的误操作是该 Over 的时候 Into，一头扎进第三方库源码里出不来。

**Watches + 即时求值。** 把关心的变量或表达式加到 Watches 面板，单步时盯着它变；`Evaluate Expression` 可以在暂停时执行任意表达式，相当于开了一个"作弊控制台"。

**调试配置别忽略。** Run/Debug Configurations 里可以设：命令行参数、环境变量、工作目录。凡是"在终端能跑、在 IDE 里跑就报错"的问题，八成是工作目录或环境变量没配对。

**调试练习靶子。** 下面这段脚本能正常跑完，但算出的平均值是错的——它漏加了最后一个分数。练习：在 `total += scores[i]` 那行打断点，用 Step Over 单步 5 次，亲眼看着 `total` 少加一次；再加个条件断点 `i == 4`，直接跳到最后一次循环看现场：

```python
def average(scores):
    """待调试版本：range 写错了一位，漏掉最后一个元素。"""
    total = 0
    for i in range(len(scores) - 1):  # BUG 在这里
        total += scores[i]
    return total / len(scores)


def average_fixed(scores):
    total = 0
    for i in range(len(scores)):
        total += scores[i]
    return total / len(scores)


if __name__ == "__main__":
    scores = [88, 92, 75, 96, 81]
    print("待调试版本算出的平均值:", average(scores))      # 70.2（错）
    print("修正版本算出的平均值:", average_fixed(scores))  # 86.4（对）
```

能用调试器在 1 分钟内定位这个 bug，就说明断点基本功过关了。

## 三、代码编辑：让 IDE 替你打字

- **智能补全**：敲几个字母就有候选，Tab 选中。如果觉得补全区分大小写碍事，去设置里关掉"大小写敏感"。
- **Alt+Enter 万能键**：光标停在报错/警告处按它，自动导入缺失的包、自动修正拼写、自动生成方法，一键消灭红色波浪线。这是全 IDE 性价比最高的快捷键。
- **重构**：`Shift+F6` 重命名变量/函数，全项目同步改，比查找替换安全得多；选中一段代码还能"提取为方法/变量"，长函数拆分利器。
- **列块编辑**：按住 `Alt` 再用鼠标纵向拖选，可以同时编辑多行，比如给 20 行一起加注释、对齐一列赋值。配合多光标（`Alt+Shift+点击`），批量改代码飞快。
- **Extend Selection**：`Ctrl+W` 按一下选中单词，再按选中表达式，再按选中整行……选中范围逐级扩大，精准选中想改的那一块。
- **Tab/空格转换**：Python 对缩进敏感，混用 Tab 和空格会报 `TabError`。IDE 能一键统一，团队协作前先统一一次。

## 四、快捷键与搜索导航：手不离键盘

记住"搜索一切"的入口，其他的用多了自然记住：

- **双击 Shift**：搜所有——文件、类、符号、甚至 IDE 的菜单动作都搜得到。忘了某个功能在哪，先双击 Shift。
- `Ctrl+N` 找类，`Ctrl+Shift+N` 找文件，`Ctrl+E` 看最近打开的文件；
- `Ctrl+B` 跳到定义，`Ctrl+Alt+B` 跳到实现（接口/抽象类专用），`Alt+F7` 找"谁在用这个函数"；
- Structure 工具窗口看当前文件的大纲（类、方法列表），长文件导航用它；
- `F11` 打书签，在几千行代码里标记"待会儿回来看"的位置。

效率的本质是减少"找东西"的时间，导航快捷键就是干这个的。

## 五、版本控制：Git 集成 + 本地历史双保险

- **Annotate（注解）**：右键行号选 Annotate，每行代码旁边显示最后是谁、哪次提交改的。接手别人的项目先看这个，少走弯路。
- **Local History（本地历史）**：IDE 自带的"后悔药"，不依赖 Git 也能用。误删了一段代码、改崩了想回去，右键文件 → Local History → Show History，按时间点恢复。这是救过无数人的功能，知道它存在就行。
- **Shelve（搁置）**：手头改了一半又要切分支救火，把改动暂存起来，回来再恢复，比 `git stash` 更直观。
- 冲突解决用 IDE 的三方合并界面（你的改动 / 最终结果 / 别人的改动），比看 `<<<<<<<` 符号直观得多。

## 六、解释器与虚拟环境：每个项目独立一片天

**为什么必须用虚拟环境。** 项目 A 要 requests 2.x，项目 B 要 requests 1.x，全装在系统 Python 里必然打架。虚拟环境给每个项目一份独立的包空间，互不干扰。

在 IDE 里操作：Settings → Project → Python Interpreter → Add → New environment（选 venv），IDE 会自动创建并切换。装包不用敲命令：解释器面板自带可视化包管理器，搜包名、选版本、点安装，还能一键导出 `requirements.txt` 给别人复现环境。

下面这段小脚本可以验证"当前用的到底是哪个解释器"——环境出问题时先跑它：

```python
import sys

print("Python 版本:", sys.version.split()[0])
print("解释器路径:", sys.executable)
# 路径里如果带了 venv/xxx，说明虚拟环境已生效
```

**远程解释器（专业版）。** 代码在本地写，实际用服务器上的 Python 跑：配一个 SSH 连接，选远端解释器，运行/调试/装包都发生在服务器上。另有 Deployment 功能把本地文件自动同步到服务器。做需要 GPU 或大数据量的开发时，这是标准姿势。

## 七、插件与数据库工具：按需武装

- **Database 工具窗口**：直连 SQLite/MySQL 等数据库，看表结构、写 SQL、看执行计划，不用在 IDE 和数据库客户端之间来回切。
- **Show Diagrams**：右键类/包生成继承关系图，读大型项目源码时先看图再看代码，脉络清晰一倍。
- **插件原则**：只装真用的，装一堆用不上的插件只会拖慢启动速度。IDE 自带的功能先摸透，八成需求不需要插件。

## 八、常用技巧速查

- **JSON 格式化**：把一团乱的 JSON 粘进 `.json` 文件，IDE 自动排版高亮，比在线格式化网站省事且不泄露数据。
- **只读文件上锁**：看源码时把文件标为只读，防止手滑改了第三方库。
- **隐藏项目树**：写代码时嫌左侧树占地方，隐藏它进入专注模式。
- **用文件管理器打开**：右键文件 → 在系统文件管理器中打开，找文件位置最快的方式。
- **内嵌 Terminal**：IDE 底部自带终端，当前项目路径、虚拟环境都已就位，不用另开窗口。

## 常见坑

1. **"包明明装了却 import 失败"**：九成是解释器选错了——终端 pip 装到了 A 环境，IDE 用的是 B 环境。先跑第六节的脚本确认解释器路径。
2. **调试时 Into 进了第三方库**：该 Over 的地方别 Into；真进去了用 Step Out 跳出来，或直接在库代码里打断点再 Resume。
3. **条件断点不触发**：检查条件表达式里的变量名在当前作用域是否存在，写错变量名断点永远等不到。
4. **索引慢、IDE 卡**：把 `node_modules`、`.git`、大数据目录 Mark as Excluded，不让索引器碰它们。
5. **Tab 和空格混用**：Python 3 直接报 `TabError`。统一用 4 空格，IDE 设置里设好，提交前检查一次。

## 练习建议

1. 拿第二节的"平均值 bug"脚本练手：打条件断点 `i == 4`，在 Watches 里盯住 `total`，单步走完并说出 bug 原因。
2. 找一段自己的旧代码，用 `Shift+F6` 给一个命名糟糕的变量改名，观察 IDE 如何全项目同步。
3. 新建一个项目，配 venv 虚拟环境，跑通第六节的解释器确认脚本，再用可视化包管理器装一个包。
4. 故意删掉一段代码，然后用 Local History 把它找回来——这个救命技能最好在"不着急"的时候先练一次。
