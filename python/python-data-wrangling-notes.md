# Python 数据处理：学习笔记

用自己的话整理的数据处理学习笔记，覆盖从拿数据、存数据、洗数据到分析和展示的全流程思路与可直接运行的代码模式。示例均为自编的模拟数据与小脚本，与任何书里案例无关。

## 1. Python 基础速览

Python 之所以适合数据处理，核心在于三点：语法直白、标准库全、第三方生态大。做数据处理时最常用的内置结构就是列表、字典和集合，外加字符串方法。

几个建议养成习惯的动作：

- 用 `type()` 看对象类型，用 `dir()` 看可用方法，用 `help()` 看文档，先看内建再想着装库。
- 版本尽量用近期的 Python 3，旧项目里的 Python 2 语法写法要逐步迁掉。
- 虚拟环境按项目隔离，依赖用 `pip freeze > requirements.txt` 锁住。

## 2. 供机器读取的数据：CSV / JSON / XML

这是数据处理的第一道工序：把文本变成程序能用的结构。

### CSV：标准库 csv 就够应付绝大多数情况

```python
import csv, io

text = "name,city,visits\n张三,北京,12\n李四,上海,7\n王五,北京,3\n"
rows = list(csv.DictReader(io.StringIO(text)))
print("CSV rows:", len(rows), rows[0]["name"])
```

实战经验：

- 永远用 `DictReader` 按表头取列，不要靠列序号硬编码，表头顺序一变就全错。
- 写文件时用 `DictWriter`，记得指定 `newline=""` 打开文件，避免 Windows 下出现多余空行。
- 编码是个常客坑：读不懂先试 `utf-8-sig`（能自动去掉 BOM），再试 `gbk`。
- 引号、逗号、换行混在一起的"脏 CSV"，让 csv 模块自己按规则解析，别手写 split。

### JSON：嵌套结构用 .get() 安全取值

```python
import json

j = json.loads('{"users": [{"name": "a", "age": 30}, {"name": "b"}]}')
print("JSON 缺字段安全取:", j["users"][1].get("age"))  # 输出 None，不抛错
```

要点：

- 取可能缺失的键用 `.get()`，深层嵌套要么逐层 get，要么写个小递归。
- 大 JSON 文件先 `json.load` 一次确认结构，再写解析逻辑。
- 日期、Decimal 这类类型 json 默认不支持，dump 时用 `default=str` 或自定义编码。

### XML：命名空间是第一大坑

```python
import xml.etree.ElementTree as ET

doc = ET.fromstring('<root xmlns="urn:x"><item id="1">苹果</item><item id="2">梨</item></root>')
ns = {"x": "urn:x"}
print("XML items:", [e.text for e in doc.findall("x:item", ns)])
```

经验：带 `xmlns` 的文档，查节点必须带命名空间映射，否则 `findall` 会返回空列表。结构复杂时先打印一层看清楚再写 XPath。

## 3. 处理 Excel 文件

Excel 文件是 `.xlsx`（zip 包）或老式 `.xls`，本质还是表格数据。操作思路分成三步：

1. 读：按工作表、按行把数据读成"表头 + 行列表"的结构。
2. 处理：在内存里清洗、汇总（逻辑同第 7、8 章）。
3. 写：生成新的工作簿，样式（加粗表头、冻结窗格、列宽）最后统一处理。

注意点：

- 日期在 Excel 里存的是数字，读出来要按日期格式转换，别当字符串用。
- 合并单元格读出来只有左上角有值，其余是空，先把合并区填满再分析。
- 数据量大时考虑分批读或转成 CSV 再处理，避免一次载入吃光内存。
- 写回时数值用数值类型、文本用文本类型写，类型写错会导致下游排序错乱。

（环境若缺第三方库，先用标准库 csv 把数据落盘，Excel 转换步骤留到有库的机器上跑，逻辑完全一致。）

## 4. 处理 PDF 文件

PDF 是"为打印而生"的格式，取文字天生别扭。通用策略：

1. 先判断 PDF 是文本型还是扫描图片型。文本型直接提取文字；扫描型要走 OCR（识别率看图片质量）。
2. 提取后按页组织文本，先抽样看 10 页，确认换行、分栏、页眉页脚的规律。
3. 用正则（见第 7 章）从正文里抓字段，而不是指望排版稳定。

常见坑：双栏排版提取后左右栏文字会串行；表格线丢失后列对不齐；页眉页脚混入正文要先过滤。处理 PDF 的基本功其实是"先接受它不完美，再用规则兜底"。

## 5. 数据获取与存储

### 先核查数据真实性

动手之前先问四个问题：这个数据是谁发布的、口径是什么（统计方法）、更新频率和最后更新时间、许可允不允许商用。不核查就进流程，分析结果可能是建立在沙子上的。

### 常见数据源

- 政府公开数据：统计、气象、交通类公开数据集，权威但格式常年不变、需要自己清洗。
- 组织与学术数据：行业报告、研究机构发布的数据集，文档齐全是优点。
- 众包数据：用户贡献的数据，覆盖面广但质量参差，必须做清洗（见第 7 章）。

### 存到哪：关系型 vs 非关系型

- 关系型（MySQL / PostgreSQL）：表结构固定、支持事务和复杂查询，适合"结构稳定、要做关联分析"的数据。
- 非关系型（文档型 / 键值型）：字段灵活、横向扩展容易，适合"结构多变、读多写多"的场景。
- 云存储：对象存储放原始文件（CSV、图片、备份），数据库放结构化结果，两者配合。

标准库里的 sqlite3 就能演示完整的"建表-插入-聚合"流程，本地原型阶段完全够用：

```python
import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE sales (id INTEGER PRIMARY KEY, city TEXT, amount REAL)")
con.executemany("INSERT INTO sales (city, amount) VALUES (?, ?)",
                [("北京", 128.5), ("上海", 99.0), ("北京", 45.0)])
con.commit()
for city, total, cnt in con.execute(
        "SELECT city, SUM(amount), COUNT(*) FROM sales GROUP BY city ORDER BY 2 DESC"):
    print(city, "合计:", total, "笔数:", cnt)
```

输出：

```
北京 合计: 173.5 笔数: 2
上海 合计: 99.0 笔数: 1
```

经验：SQL 里的聚合（SUM/COUNT/GROUP BY）做汇总比把数据全拉出来再用 Python 算要快得多，养成"能下推到数据库的计算就下推"的习惯。

## 6. 数据清洗一：研究、匹配与格式化

清洗是数据处理里最花时间的一步，几个标准动作：

### 离群值：IQR 法

```python
import statistics
vals = [12, 11, 13, 12, 10, 11, 98, 12]
qs = statistics.quantiles(vals, n=4)
iqr = qs[2] - qs[0]
lo, hi = qs[0] - 1.5 * iqr, qs[2] + 1.5 * iqr
print("正常区间:", (round(lo,1), round(hi,1)), "离群值:", [v for v in vals if v < lo or v > hi])
```

输出：正常区间 (8.4, 15.4)，离群值 [98]。注意：离群值不等于错误值，先核实再决定删除还是修正。

### 重复值：按关键字段去重

```python
seen, rows = set(), []
for r in [("张三","北京"), ("李四","上海"), ("张三","北京")]:
    if r not in seen:
        seen.add(r); rows.append(r)
print("去重后:", rows)  # [('张三', '北京'), ('李四', '上海')]
```

### 模糊匹配：先归一化再比相似度

```python
from difflib import SequenceMatcher

def similar(a, b):
    return SequenceMatcher(None, a, b).ratio()

print("相似度:", round(similar("北京市朝阳区", "北京朝阳区"), 3))  # 0.909
```

实战流程：先统一大小写、全角半角、去除多余空格（归一化），再算相似度，设阈值（如 0.85）自动合并，阈值附近的留人工复核。不要全自动合并，误杀的代价很高。

### 正则：从文本里抓字段的瑞士军刀

```python
import re

date_pat = re.compile(r"\d{4}[-/]\d{1,2}[-/]\d{1,2}")
money_pat = re.compile(r"￥\d+(?:\.\d{2})?")

for r in ["订单2024-01-31金额￥128.50", "联系13800138000 2023/12/5", "无效信息"]:
    d = date_pat.search(r)
    m = money_pat.search(r)
    print(repr(r), "-> 日期:", d.group(0) if d else None, "| 金额:", m.group(0) if m else None)
```

输出：

```
'订单2024-01-31金额￥128.50' -> 日期: 2024-01-31 | 金额: ￥128.50
'联系13800138000 2023/12/5' -> 日期: 2023/12/5 | 金额: None
'无效信息' -> 日期: None | 金额: None
```

经验：

- 正则先 `re.compile` 预编译，复用时更快。
- 能用简单模式就别写复杂模式，贪婪匹配是头号 bug 来源。
- 抓不到的先打印原文看规律，八成是多了个全角字符或换行。

### 文本归一化小抄

```python
s = "　全　角　价 1,299.00　"
s = s.translate(str.maketrans("　", " ")).strip()
s = re.sub(r"\s+", " ", s)
print("清洗后:", repr(s))  # '全 角 价 1,299.00'
```

## 7. 数据清洗二：标准化与脚本化

清洗规则一旦在交互式环境里调通，立刻固化成脚本。推荐结构：

1. `load()`：读原始数据，原样不动。
2. `clean(df)`：所有清洗步骤按函数拆分，一个函数只做一件事（去空值、统一日期格式、统一单位……）。
3. `validate()`：清洗后跑校验：非空约束、取值范围、主键唯一，发现问题抛错而不是静默通过。
4. `save()`：写出干净数据 + 一份清洗日志（改了多少行、删了多少行、原因）。

关键点：

- 原始数据永远只读不写，清洗结果写新文件。
- 每个清洗决策写进日志：比如"删除 37 行缺失关键字段"，可追溯。
- 日期格式统一成 ISO（YYYY-MM-DD），金额统一单位，城市名统一用标准名。
- 清洗脚本要可重复运行：同样的输入跑两次，结果必须一致（幂等）。

## 8. 数据探索与分析

动手分析前先做描述统计，对数据有个整体感觉：

```python
import statistics
x = [1, 2, 3, 4, 5, 6, 7, 8]
y = [2.1, 4.0, 6.2, 8.1, 9.9, 12.2, 13.8, 16.1]
print("均值:", statistics.mean(x), "中位数:", statistics.median(x),
      "标准差:", round(statistics.pstdev(x), 3))
print("相关系数:", round(statistics.correlation(x, y), 4))
```

输出：

```
均值: 4.5 中位数: 4.5 标准差: 2.291
相关系数: 0.9996
```

常用清单：

- 均值、中位数、众数看集中趋势；标准差、四分位数看离散程度。
- 中位数比均值更抗离群值，收入这类偏态数据优先看中位数。
- 相关系数看两个变量是否同向变化，但**相关不等于因果**，看到强相关先找业务解释。
- 分组汇总（按城市、按月份）往往比全局统计更有信息量。

## 9. 展示数据：可视化与讲故事

图表是手段，结论才是目的。几点原则：

- 一张图只讲一个结论，标题直接写结论（而不是"销售额统计"）。
- 选图看数据类型：趋势用折线、对比用柱状、构成用堆叠或饼（类别少时）、分布用直方图。
- 坐标轴从 0 开始（柱状图），不截断误导；单位、时间范围标注清楚。
- 交互式笔记本（Jupyter）适合边分析边展示，文字说明和代码放一起，别人能复现你的结论。
- 讲故事的结构：背景 → 发现 → 证据（图表）→ 建议，下一步行动要明确。

## 10. 网页抓取：基础

抓取四步：发请求 → 拿 HTML → 解析提取 → 存下来。

```python
import urllib.request

req = urllib.request.Request(
    "https://api.github.com/zen",
    headers={"User-Agent": "study-notes-demo"})
try:
    with urllib.request.urlopen(req, timeout=10) as resp:
        print("HTTP", resp.status, "->", resp.read().decode()[:60])
except Exception as e:
    print("网络不可用，降级:", type(e).__name__)
```

输出示例：`HTTP 200 -> It's not fully shipped until it's fast.`

要点：

- 发请求带上合理的 User-Agent 和超时，别让程序无限卡住。
- 解析 HTML 优先用解析库按标签/类名定位，别用正则硬抠 HTML。
- 先看网站有没有 robots.txt，尊重抓取频率，加延时，别把人家服务器打挂。
- 有官方 API 的优先用 API（见第 12 章），抓取是最后手段。

## 11. 高级网页抓取：屏幕抓取器与爬虫

当页面是 JavaScript 渲染、或需要登录、翻页时，难度上升：

- 动态页面：先看网络请求，很多"动态"数据其实是某个 JSON 接口，直接调接口比渲染页面省事得多。
- 需要登录的：维护会话（cookie），把登录态保存在本地，过期再重新登录。
- 爬虫：广度优先遍历链接，维护已访问集合去重，设置最大深度和域名白名单，防止爬到外网去。
- 反爬应对：降频、换 User-Agent、处理验证码（能避则避，硬刚成本高）。
- 数据落地：边爬边存，别等全爬完再写，中间断了不至于全丢。

## 12. 应用程序接口（API）

API 是拿数据的正道：结构稳定、有文档、有版本。通用模式：

1. 读文档：认证方式（API Key / OAuth）、限流规则、分页方式。
2. 封装请求函数：统一处理超时、重试、错误码。
3. 分页拉全量：按游标或页码循环，直到没有下一页。
4. 存原始响应：先把 JSON 原样落盘，再解析入库，接口变了还能回溯。

注意点：

- Key 不要写进代码，用环境变量或配置文件。
- 限流（429）要退避重试，别硬怼。
- 免费额度用完前设提醒，别等到被停了才发现。

## 13. 自动化与规模化

当流程跑通一次，就该考虑自动化：

- 定时任务：cron / 计划任务，按小时、天、周调度脚本。
- 增量更新：只拉新增数据，用时间戳或 ID 做水位线，别每次全量重跑。
- 日志与告警：每次运行记日志（成功/失败、处理量、耗时），失败发通知，别让任务静默挂掉。
- 参数化：把日期、路径、阈值做成参数，别写死在代码里。
- 规模化三板斧：分批处理（chunk）、并行（多进程/多线程）、能下推到数据库的计算不自己算。

## 14. 常见陷阱

- **编码坑**：乱码先查编码，`utf-8-sig` 和 `gbk` 轮流试，别靠猜。
- **日期坑**：`01/02/03` 美式是月/日/年，解析前确认格式；时区统一成 UTC 再计算。
- **浮点坑**：金额计算用 Decimal 或转成"分"用整数算，`0.1 + 0.2` 的经典问题别在账上重演。
- **空值坑**：空字符串、"NULL"、"N/A"、"—"都是空值，清洗时统一识别。
- **类型坑**：CSV 读出来全是字符串，数字、日期要显式转换，转换失败要报错而不是静默跳过。
- **相关≠因果**：分析结论先过业务常识这一关。
- **原始数据只读**：任何清洗都不动源文件，出问题随时能重来。
- **先小规模验证**：新流程先在 100 行样本上跑通，再全量。
