# 从 Python 开始学编程 · 学习笔记

**本书定位**：一本面向纯零基础读者的 Python 入门书，用大量生活化比喻把抽象概念讲具体，适合第一次接触编程的人先建立"程序能做什么"的直觉，再补语法细节。（本笔记依据某 Python 入门书的章节结构整理。）

## 一、用编程改造世界：计算机与编程的概念

- 程序的本质，是把"让计算机做事的步骤"写下来。计算机本身只懂按指令办事，它不会自己理解你的意图，所以编程就是把你的想法翻译成计算机能执行的明确步骤。这是全书的地基：先接受"计算机很笨、但执行力极强"这个设定，后面学语法才有方向感。
- 为什么选 Python 作为第一门语言？因为它离人类的表达习惯最近。用它写第一句"Hello World"，只需要一行打印语句，不用先搞懂编译、类型声明这些周边概念。初学者最大的敌人是挫败感，Python 把"看到成果"的门槛压到最低，先跑起来再说。
- 环境搭建是第一道坎：装好解释器、能运行脚本、知道什么是虚拟环境。虚拟环境的核心作用是隔离——不同项目依赖的库版本可能互相打架，每个项目配一个独立的小房间，谁也不影响谁。初学阶段先会用，再理解原理。

## 二、先做键盘侠：算术、变量、条件与循环

- 变量就是"给数据起个名字存起来"。程序里几乎所有操作都是"取数据、算一算、存回去"的循环。理解这一点后，赋值语句就不再是死记的语法，而是在"搬运和加工数据"。
- 条件选择（if）是程序第一次"有了判断力"：如果满足某个条件就走这条路，否则走那条路。现实世界里"如果下雨就带伞"这样的逻辑，原样搬进代码就行。初学者常犯的错是把"等于"写成赋值号，这是从数学符号切换到编程符号的第一课。
- 循环（for / while）是"让计算机替你重复劳动"的起点。for 适合"把一堆东西逐个过一遍"，while 适合"某个条件成立就一直做"。写循环最关键的是想清楚"什么时候停"，停不下来的循环就是死循环，while 循环里一定要有让条件发生变化的语句。
- 代码规范不是形式主义：统一的缩进和命名，是让别人（包括三个月后的你自己）能读懂代码的最低成本。Python 用缩进来表示代码块，缩进错一位程序就变了意思，写的时候就要养成"缩进即结构"的肌肉记忆。

## 三、过程大于结果：函数、递归、模块与异常

- 函数是"给一段步骤起个名字，以后直接喊名字就能用"。它的真正价值不在于少打字，而在于把复杂问题切成小块：每个函数只干一件事，出了问题就知道去哪一块找。参数是"调用时传进来的原料"，返回值是"做完交出来的成品"。
- 递归是"函数自己调用自己"，适合解决"大问题可以拆成同样的小问题"的场景，比如阶乘、遍历树形结构。写递归必须同时想好两件事：拆分的规则，以及什么时候停（终止条件）。没有终止条件的递归会一直调用到栈溢出，这是新手最容易踩的坑。
- 模块是"别人写好的工具箱"，用 import 拿来直接用，不用重复造轮子。Python 自带了丰富的标准库，文件操作、时间日期、数学计算都有现成的。理解"标准库—第三方库—自己写的模块"这三层，能帮你快速判断一个功能该去哪里找。
- 异常处理是"给程序买保险"：try 去做可能出错的事，except 规定出错了怎么办。文件不存在、网络断了、用户输入了非法数字，这些都是运行时才会遇到的情况。好习惯是"只捕获你知道怎么处理的异常"，不要用一个空的 except 把所有错误吞掉，那样会把真正的 bug 藏起来。

## 四、朝思暮想是对象：面向对象入门与继承

- 面向对象的核心思想是"把数据和操作数据的方法打包在一起"。比如一个"计数器"，它的数值和"加一"这个动作天然是一体的，写成一个类，创建出来的每个对象都自带这套行为。这样代码的组织方式就从"一堆散落的函数"变成了"一个个有职责的零件"。
- 类是图纸，对象是按图纸造出来的实物。一个类可以造出无数个对象，每个对象有自己独立的数据（比如两个计数器的数值互不干扰），但共享同一套方法。初学者要反复体会"类"和"对象"的区别，这是面向对象里最重要的一道分水岭。
- 继承是"站在已有图纸上改一改，变成新图纸"。子类自动拥有父类的全部能力，只需要写新增或改写的部分。它解决的是代码复用的问题：相似的东西不用从头写两遍。但继承层级太深会让关系变复杂，入门阶段记住"is-a 关系才用继承"就够了（狗是一种动物，所以狗类继承动物类）。

## 五、对象带你飞：文件、时间、正则、网络与爬虫

- 文件存储是程序"记住东西"的方式：把内存里的数据写进硬盘，下次打开还能接着用。读写文件就三步：打开、读写、关闭（用 with 语句可以自动关闭，推荐）。文本文件注意编码，中文环境下明确指定 utf-8 能避开一大半乱码问题。
- 时间和日期处理看着简单，坑却不少：时间戳、格式化字符串、时区是三个最容易混的概念。记住一个原则——存储和计算用时间戳或标准对象，只在展示给人看时才转成字符串，时区问题永远在边界（输入输出）处处理。
- 正则表达式是"用一套特殊符号描述文本长什么样"，专门用来从大段文字里抠出符合规则的内容，比如电话号码、邮箱地址。它很强大但可读性差，入门阶段掌握"匹配数字、匹配重复、分组提取"这几个基本功就够用，复杂的 pattern 写完一定要加注释。
- 网络编程和爬虫是把"程序"和"世界"连起来的章节：发请求、拿响应、解析网页内容。爬虫的本质就是"自动化的浏览器浏览"：请求页面、提取想要的数据、存下来。动手时要注意两点：遵守目标网站的规则和频率限制，以及网页结构变化会导致解析代码失效，解析逻辑要写得有弹性。

## 六、与对象的深入交往：一切皆对象、装饰器与内存管理

- Python 里"一切皆对象"：数字、字符串、函数、类本身都是对象，都有类型、属性和方法。这个统一性带来一个很实用的推论——函数也可以像数据一样被传递、被赋值给变量，这是装饰器和高阶函数存在的前提。
- 属性管理讲的是"对象的数据怎么存、怎么取"。直接暴露内部数据虽然省事，但别人可以随意改，容易埋雷。用方法或 property 来管控读写，就能在"方便"和"安全"之间取得平衡。入门阶段先养成"不直接碰别人的内部数据"的意识。
- 装饰器是"给函数穿外套"：不改函数本身的代码，在外面包一层，额外加上日志、计时、权限检查这类通用功能。它看起来神奇，拆开看就是"函数接收函数、返回新函数"——一旦理解函数是一等公民，装饰器就只是水到渠成的一个应用。
- 内存管理方面，Python 用引用计数加垃圾回收自动处理内存，程序员一般不用手动释放。但要知道"循环引用"这个概念：两个对象互相指着对方，引用计数就清不掉它们，好在 Python 的垃圾回收器能处理这种情况。日常写代码记住一条：不需要长期持有的数据就及时释放引用（比如大列表用完就 del 或让它离开作用域）。

## 七、函数式编程：lambda、闭包与高阶函数

- lambda 是"随手写一个小函数"，适合那种只用一次、逻辑只有一行的场景，比如给排序指定"按哪个字段排"。它不是为了炫技，而是为了"让代码的意图离使用它的地方更近"，省去为一个小逻辑单独起名的负担。
- 闭包是"函数记住了它出生时的环境"。一个内部函数引用了外部函数的局部变量，即使外部函数已经执行完，这个变量还活着。它的实际用途是"定制函数"：比如写一个"生成加 N 器"的函数，调用它三次就得到三个行为不同的函数。
- 高阶函数是"把函数当参数传来传去"，map、filter、sorted 的 key 参数都是这个思想。它的好处是把"做什么"和"对谁做"分开：遍历的逻辑写一遍，具体的动作由传入的函数决定。这种"行为参数化"是写出灵活代码的关键技巧，也是理解装饰器的前置知识。

## 手写代码示例（已在本机 Python 3.12 验证通过）

```python
def log_calls(fn):
    """简单的日志装饰器：打印函数名、参数和返回值"""
    def wrapper(*args, **kwargs):
        print(f"调用 {fn.__name__}，参数={args}")
        result = fn(*args, **kwargs)
        print(f"返回 {result}")
        return result
    return wrapper


class Counter:
    """一个计数器类：用对象把'数值'和'操作数值的动作'包在一起"""
    def __init__(self):
        self.count = 0

    @log_calls
    def add(self, n=1):
        self.count += n
        return self.count


def factorial(n):
    """递归求阶乘：函数自己调用自己，记得一定要有终止条件"""
    if n <= 1:
        return 1
    return n * factorial(n - 1)


def safe_divide(a, b):
    """演示异常处理：除数为 0 时不让程序崩溃"""
    try:
        return a / b
    except ZeroDivisionError:
        return "除数不能为 0"


if __name__ == "__main__":
    c = Counter()
    c.add(3)
    print("5 的阶乘是", factorial(5))
    print("10 / 0 的结果：", safe_divide(10, 0))
    print("计数器当前值:", c.count)
```

## 常见坑

1. 缩进混用空格和 Tab：看起来对齐了，解释器却报错，统一用 4 个空格。
2. 可变对象当默认参数（如 `def f(lst=[])`）：默认参数只创建一次，多次调用会累积数据，改用 `None` 再在函数内新建。
3. 递归忘了终止条件：直接栈溢出，写递归先写"什么时候停"。
4. 裸 except 吞掉所有异常：调试时找不到真正的错误，只捕获明确的异常类型。
5. 文件读写不指定编码：中文乱码的头号来源，open 时加上 `encoding="utf-8"`。
