# 微信小程序开发课程地图

这套课程一共八十四讲，从"小程序是什么"一直讲到"上线一个完整项目"，脉络很清楚：先讲生态和工具，
再讲语言三件套，接着讲框架原理和组件，然后铺开各类 API（网络、设备、多媒体、开放能力），
最后用一个"小书架"实战项目把前面所有东西串起来收尾。笔记按课程的模块顺序整理，
每个模块说清楚三件事：这组课在学什么、为什么重要、一个值得记住的关键点。

## 一、背景与生态：先搞懂小程序长成今天这个样子

开篇几讲先交代来龙去脉：小程序是跑在微信客户端里的轻应用，用户不用下载安装，扫码或者搜索就能用，
用完即走。对开发者来说，这意味着流量入口极大，但代价是必须接受微信定制的开发体系和审核规则，
上线前要过审，更新也要走发布流程。记住一个关键点：小程序不是"网页套壳"，它有自己独立的运行环境和渲染机制，
带着网页开发的经验来，要先放下"这就是 H5"的预设，否则很多设计会觉得别扭。

## 二、开发者工具：先把趁手的家伙什配好

正式写代码之前，课程带着装好官方开发者工具，熟悉界面分区：模拟器、编辑器、调试器、项目配置各管什么。
工具里能直接预览真机效果、打断点、看网络请求和本地存储，开发效率一大半靠它。
一个值得记住的习惯：从第一天就养成用真机扫码预览做最终确认，模拟器和真机在字体渲染、性能表现上都有细微差别，
交付前别偷懒，凡是只在模拟器上跑过的页面，真机上都可能给你"惊喜"。

## 三、语言基础：WXML、WXSS 与 JavaScript

小程序的界面用 WXML 描述结构，用 WXSS 描述样式，逻辑层写 JavaScript，三者分工和网页的 HTML、CSS、JS 高度对应，
但细节处处不同。WXML 支持数据绑定、条件渲染和列表渲染，WXSS 多了一个 rpx 单位专门做屏幕适配，
逻辑层的 JS 没有 BOM 也没有 DOM，只能通过框架提供的 API 和 setData 跟视图通信。
关键点只有一句：视图层和逻辑层是隔离的，改数据必须走 setData，直接改 this.data 页面不会刷新——
新手十个"页面没反应"里有九个栽在这里。

下面是一组我自己写的、能直接跑通的小例子：一个书架卡片，展示数据绑定、条件渲染、列表渲染和事件绑定。

```xml
<!-- pages/books/books.wxml -->
<view class="card">
  <text class="title">{{book.title}}</text>
  <text class="author">{{book.author}}</text>
  <button bindtap="onAdd">加入书架</button>
</view>
<view wx:if="{{books.length === 0}}">
  <text>书架是空的，去挑几本书吧</text>
</view>
<view wx:for="{{books}}" wx:key="id">
  <text>{{index + 1}}. {{item.title}}</text>
</view>
```

```css
/* pages/books/books.wxss */
.card { background: #fff; border-radius: 16rpx; padding: 24rpx; margin: 20rpx; }
.title { font-size: 34rpx; font-weight: bold; color: #1a1a1a; }
.author { font-size: 26rpx; color: #888; margin-top: 8rpx; }
```

上面 WXSS 里用的 rpx 是小程序特有的自适应单位：规定屏幕宽为 750rpx，
在 iPhone 6 这种 375px 宽的屏幕上，1rpx 就等于 0.5px，写一套样式就能适配各种机型，
这是它比 px 省心的地方。

```js
// pages/books/books.js
Page({
  data: {
    book: { title: '示例书名', author: '示例作者' },
    books: []
  },
  onAdd() {
    const list = this.data.books.concat(this.data.book);
    this.setData({ books: list });
    wx.showToast({ title: '已加入书架', icon: 'success' });
  }
});
```

注意 onAdd 里先拼好新数组再一次性 setData，而不是在循环里反复调用 setData，
后者会让视图层白白重渲染好几次，数据量一大就卡。
另外课程里第 20 讲专门补了一讲 JavaScript 介绍，说明这门课默认读者可能 JS 基础不牢。
如果学到后面觉得吃力，回头把这一讲多看两遍是值得的，原型、闭包、异步回调这几个概念在小程序里天天见面。

## 四、WXS 与 MINA 框架：理解小程序的"骨架"

WXS 是一套跑在视图层的小脚本语言，语法长得像 JavaScript，专门用来在 WXML 里做简单的数据处理，
比如格式化价格、截断过长的字符串。它的意义在于：有些小事没必要惊动逻辑层，在视图层就地解决，页面渲染更快。
MINA 框架是小程序底层的设计思想——视图层和逻辑层双线程运行，通过数据通道通信。
理解了这个模型，很多"为什么"的疑问（比如为什么没有 window 对象、为什么不能直接操作 DOM）就自然解开了。

```wxs
// tools.wxs：在视图层直接格式化价格
function formatPrice(p) {
  return '¥' + p.toFixed(2);
}
module.exports = { formatPrice: formatPrice };
```

## 五、组件：搭界面的乐高积木

组件部分是课程里篇幅最长的一块：view、text、icon、progress 这类基础展示组件，
button、form、input、checkbox、radio、slider、textarea 这套表单组件全家桶，
swiper 轮播、navigator 页面跳转、map 地图、canvas 画布，再加上 movable-view 可拖动区域、
cover-view（专门盖在原生组件上层的特殊视图，解决原生组件层级最高的老大难问题）。
新增讲次里还补了三个重量级组件：video 视频播放、live-player 直播拉流、web-view 内嵌网页。
关键点：能用现成组件就别自己造轮子，尤其是 map、canvas、video 这类原生组件，
自己用 canvas 重画一张地图纯属折磨自己；但反过来，组件的默认样式往往很素，WXSS 美化是必修课。

## 六、网络 API：跟服务器说话的几种方式

网络模块围绕四件事：wx.request 发普通 HTTP 请求拿数据，上传下载两套 API 传文件，
WebSocket 做长连接收实时消息。课程里专门用两讲把"网络请求"和"上传下载"拆开讲，
说明文件传输的坑值得单独对待：进度回调、大文件超时、切到后台上传被系统杀掉，都是真机上才会暴露的问题。
记住一个铁律：所有请求的域名必须先在小程序后台加白名单，开发时忘了配，request 直接失败还不给详细报错，
新手经常在这里浪费一下午，对着代码找 bug，结果问题出在后台配置里。

```js
// 拉取书籍列表：成功更新视图，失败给用户一个明确提示
Page({
  data: { books: [], loading: true },
  onLoad() {
    wx.request({
      url: 'https://api.example.com/books',
      success: (res) => {
        this.setData({ books: res.data, loading: false });
      },
      fail: () => {
        this.setData({ loading: false });
        wx.showToast({ title: '加载失败，请检查网络', icon: 'none' });
      }
    });
  }
});
```

## 七、设备与多媒体 API：调动手机的硬件能力

这一组课是小程序区别于普通网页的底气所在：设备信息、加速度计、蓝牙、地图定位、
图片选择与预览、录音与音频播放、文件读写、本地数据缓存、界面交互（弹窗、loading、导航栏设置）、动画 API、canvas 绘图。
新增讲次把"数据缓存""文件应用""其他设备""绘图"单独成讲，覆盖了本地存储读写和 canvas 2D 绘图这些动手性很强的内容。
关键点：凡是涉及用户隐私的（位置、相册、麦克风），都要先申请授权，还要处理用户点了拒绝之后的情况，
否则轻则功能瘫痪，重则审核被打回。另一个细节是本地缓存有大小上限，别把图片 base64 一股脑塞进去。

```js
// 本地缓存：把用户上次看的书 id 存下来，下次打开直接恢复
wx.setStorageSync('lastBookId', 'book_1001');
const lastId = wx.getStorageSync('lastBookId');
console.log('上次看到：', lastId);
```

## 八、登录、支付与开放能力：小程序真正的护城河

登录授权讲的是微信登录闭环：前端 wx.login 拿到一个临时 code，把它传给自己的后端，
后端拿 code 去换用户的身份标识，之后所有接口都认这个身份。
支付讲的是微信支付的接入流程：统一下单在后端做，前端只负责调起支付控件，并处理成功和失败两种回调。
转发分享和模板消息属于开放能力，决定了小程序的传播手段和触达用户的手段。
页面路由（wx.navigateTo、wx.redirectTo、wx.navigateBack）也在这一带讲清：什么时候压栈、什么时候替换、什么时候返回，
页面栈最多十层，跳超了会报错，做多级详情页时要提前规划。
关键点：code 只能用一次、几分钟就过期，登录态要靠自己后端维护的会话，别指望前端存个标识就万事大吉；
支付金额永远以后端计算为准，前端传的价格只能当展示用，这是防刷单的基本安全意识。

## 九、WePY 框架：给大型项目换一套写法

第 90 讲单独讲了 WePY——一套类 Vue 语法的框架，写完之后编译成标准的小程序代码运行。
它解决的是项目变大之后原生写法难以维护的问题：组件化拆分、复用、状态管理，都有了更顺手的组织方式。
关键点：框架是手段不是目的，只有几个页面的小项目，原生写法反而更快；
只有当你开始觉得"代码越写越乱、改一个地方处处冒烟"时，才是考虑上框架的时机。
学这一讲时别纠结语法细节，重点看它"为什么要这样组织代码"，这个思想搬到任何框架都通用。

## 十、性能优化：上线前必须过的一关

第 91 讲收尾谈性能：首屏加载速度、包体积控制、setData 的数据量节制、图片资源压缩、长列表的渲染优化。
课程把它放在最后讲是有深意的——功能跑通只是及格线，低端机上不卡、弱网下能用，才是能交付的水平。
记住几个具体的动作：setData 只传变化的那部分数据，别把整个页面数据一把梭过去；
图片能上压缩就别传原图，列表页用缩略图、详情页再加载大图；首屏只渲染首屏要的东西，其他的按需加载。
优化没有银弹，就是把这些小事一件一件做到位。

## 十一、实战项目：小书架

最后的大项目是一个"小书架"应用：先做项目演示和开发准备，把架子搭起来，
然后逐个实现书籍列表、书籍详情、评论消息、已购书籍、个人中心几个模块。
每个模块都是一次综合演练：列表页练网络请求和列表渲染，详情页练路由传参，
评论模块练表单提交和数据校验，已购书籍练登录态下的数据过滤，个人中心把登录、缓存、界面设置串在一起。
关键点：跟着做完一遍之后，合上视频自己从零重写一遍，凡是卡住的地方就是你没真懂的地方；
重写时故意换个需求（比如把书架改成电影收藏），能改出来才算真学会了。
