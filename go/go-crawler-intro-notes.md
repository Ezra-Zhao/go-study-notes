# Go 爬虫第一讲：爬虫是什么，为什么用 Go

> 想系统地抓公开网页数据，先搞清楚"爬虫"到底是个什么东西，再决定用什么语言写它。

## 一、一句话说清爬虫

网络爬虫就是一段程序：它按照你定好的规则，自动打开网页、把公开的信息取回来、整理成你要的样子。

换个说法，它是个"替人翻网页的助手"——人翻十页就累了，它翻一万页不眨眼。它的价值不取决于技术本身，而取决于你让它翻什么、拿来干什么。

## 二、合规的用途长什么样

先把正道列清楚，技术才有安放的地方：

- **自有网站可用性监控**：定时抓自己网站的页面，看有没有挂、加载慢不慢；
- **公开数据聚合分析**：收集公开的商品价格、学术文献目录，做统计分析；
- **搜索引擎索引**：搜索引擎的网页索引，本质上就是大规模爬虫。

共同点：要么抓的是自己的东西，要么抓的是公开信息，且用途正当。

## 三、为什么选 Go

写爬虫的语言很多，Go 有三个实在的好处：

1. **标准库一次到位**：`net/http` 负责发请求，`regexp` 负责从文本里抠数据，开箱即用，不用先装一堆第三方包；
2. **并发成本低**：`goroutine` 启动开销极小，几百个页面同时抓也不吃力，配合 `channel` 收结果，代码比传统多线程清爽；
3. **部署省心**：编译出来是单个二进制文件，拷到服务器上直接跑，不用配运行环境。

## 四、最小可运行示例：抓一个页面的标题

下面这段程序用 Go 标准库实现"爬虫"最核心的动作：发请求、拿 HTML、提取标题。为了不打扰真实网站，示例里用 `httptest` 起一个本地测试服务器代替目标网站——思路和抓真实页面完全一样：

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"regexp"
)

func main() {
	// 本地测试服务器：代替真实网站，返回一个带标题的页面
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprint(w, `<html><head><title>演示页面</title></head><body>hello</body></html>`)
	}))
	defer ts.Close()

	// 发请求
	resp, err := http.Get(ts.URL)
	if err != nil {
		fmt.Println("请求失败:", err)
		return
	}
	defer resp.Body.Close()
	body, _ := io.ReadAll(resp.Body)

	// 用正则提取标题
	titleRe := regexp.MustCompile(`<title>([^<]+)</title>`)
	m := titleRe.FindStringSubmatch(string(body))
	if len(m) == 2 {
		fmt.Println("页面标题:", m[1])
	} else {
		fmt.Println("没找到标题")
	}
}
```

运行输出：

```
页面标题: 演示页面
```

这段代码麻雀虽小，五脏俱全：**发请求 → 拿回 HTML → 提取目标数据**。后面几讲就是把每一步做扎实：先看合规红线，再学行为规范、正则提取、分页规律、HTTP 封装，最后用并发把整条链串起来。

## 五、本讲小结

- 爬虫 = 按规则自动浏览网页、抓回公开信息整理好的程序，本质是替人翻网页的助手；
- 合规用途：自有网站监控、公开数据聚合、搜索引擎索引；
- 选 Go 的三理由：标准库齐、并发轻、部署简单；
- 全系列技术链条：**找分页规律 → 发请求 → 正则提取 → 并发加速**，合规意识先行。
