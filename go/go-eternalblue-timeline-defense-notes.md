# 认识永恒之蓝：从一条漏洞时间线学会补丁管理

> 学这一讲不是为了研究攻击，而是看清一个著名漏洞是怎么从"已公开"变成"大爆发"的——防御方的教训只有一条：补丁不能拖。

## 一、时间线：从公开到爆发只隔了一个月

把几个公开记录里的时间点摆出来看：

- **2017-04-14**：影子经纪人（Shadow Brokers）在网上公开了一批工具，其中包含针对 Windows SMB 服务漏洞的利用代码，这个漏洞后来被称作"永恒之蓝"；
- **2017-05-12**：WannaCry 大规模爆发，它利用的正是上面这个 SMB 漏洞，在全球造成大面积影响；
- **补丁 MS17-010**：微软在漏洞公开前后就发布了修复补丁，编号 MS17-010。打了补丁的机器不受影响，没打的成了重灾区。

三件事连起来看，结论很扎心：**补丁早就有了，出事的都是没打补丁的**。漏洞从"公开"到"被大规模利用"，窗口期只有一个多月。

## 二、SMB 是个什么东西

SMB（Server Message Block）是 Windows 上用了几十年的文件共享协议：局域网里共享文件夹、共享打印机，背后走的都是它。很多机器默认开着 445 端口提供 SMB 服务，内网里一台中招，同一网段的机器就都暴露在风险下。

防御视角记住两点就够了：

1. **不用的服务就关掉**：个人电脑不需要给局域网共享文件，445 端口没必要对外开；
2. **补丁是第一道防线**：系统更新提示出来就装，MS17-010 这类安全补丁不要拖到"有空再说"。

## 三、动手自查：本机 445 端口开着吗

下面这段 Go 程序做一件很小的防御性检查：尝试连接本机的 445 端口，看 SMB 服务有没有在监听。连不上说明端口没开，这是好消息。

```go
package main

import (
	"fmt"
	"net"
	"time"
)

func main() {
	target := "127.0.0.1:445"
	conn, err := net.DialTimeout("tcp", target, 2*time.Second)
	if err != nil {
		fmt.Printf("本机 %s 未开放（连接失败：%v），SMB 服务不在监听，好事。\n", target, err)
		return
	}
	defer conn.Close()
	fmt.Printf("本机 %s 有服务在监听，请检查是否真的需要开 SMB 共享，不需要就关掉。\n", target)
}
```

运行结果（示例）：

```
本机 127.0.0.1:445 未开放（连接失败：dial tcp 127.0.0.1:445: connect: connection refused），SMB 服务不在监听，好事。
```

## 四、本讲小结

- 永恒之蓝是 Windows SMB 服务的漏洞，2017-04-14 被公开，2017-05-12 被 WannaCry 大规模利用；
- 微软补丁 MS17-010 早已发布，打补丁的机器安然无恙；
- 防御三板斧：**及时打补丁、不用的服务关掉、内网机器不共用弱口令**；
- 上面的端口自查脚本可以定期跑一跑，确认 445 这类高危端口没有意外开放。
